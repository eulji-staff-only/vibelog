## 1. 준비 (5분)

1. 최신 코드를 받습니다: `git switch develop` → `git pull origin develop`
2. 최초 1회 `sql/00-create-database.sql`을 실행합니다.
   Workbench에서 로컬 연결과 `vibelog` 데이터베이스를 선택한 뒤 `sql/01-schema.sql` → `sql/02-seed.sql`을 차례로 실행합니다.
   실행 전에 대상과 백업을 확인하세요. `vibelog`의 기존 데이터는 삭제됩니다.
3. 앱을 실행합니다: `./gradlew bootRun` 또는 IntelliJ에서 `VibelogApplication`. 주소는 `http://localhost:8080`입니다.
4. 확인에 쓸 계정을 정합니다.

| 계정 | 로그인 | 볼 수 있는 것 |
|---|---|---|
| 비회원 | 로그아웃 상태 | 랜딩, 트랙·코스 소개, 게시판 목록·상세 |
| 학습자 | `learner@vibelog.test` | 회원 화면 전체 (비밀번호는 팀 채팅) |
| 운영자 | `admin@vibelog.test` | `/admin` 백오피스 (비밀번호는 팀 채팅) |

> 💡 테스트를 돌린 뒤나 직접 눌러 본 뒤에 데이터가 꼬이면 2번(SQL 01 → 02)을 다시 하면 처음 상태로 돌아갑니다.

## 3. 어떻게 확인하나

한 화면마다 아래 순서로 봅니다.

1. **정상 흐름:** 화면 설계서(`docs/design/01-screen-flow.md`)에 적힌 대로 끝까지 눌러 봅니다.
2. **예외 흐름:** 빈 입력, 너무 긴 입력, 이미 있는 값, 잠긴 화면, 없는 주소를 시도해 봅니다.
3. **권한:** 비회원 · 학습자 · 운영자로 같은 주소를 열어 봅니다. 열리면 안 되는 화면이 열리지 않는지 봅니다.
4. **화면 폭:** 브라우저 폭을 줄여 모바일 폭(약 400px)에서도 깨지지 않는지 한 번 봅니다.

### 한 화면에서 볼 것
- [ ] 화면이 열린다 (오류 화면이 아니다)
- [ ] 값이 맞게 나온다 (숫자·이름·날짜)
- [ ] 버튼과 링크가 설계서의 화면으로 이동한다
- [ ] 입력 오류 메시지가 원인과 다음 행동을 알려 준다
- [ ] 데이터가 없을 때 빈 상태 문구가 나온다 (빈 화면이 아니다)
- [ ] 새로고침, 뒤로 가기를 해도 이상하지 않다
- [ ] 토스트·안내 문구가 한 번만 나온다
- [ ] 브라우저 개발자 도구(F12) 콘솔에 빨간 오류가 없다

> 시드 데이터가 적어서 "집계된 데이터가 없습니다"로만 보이는 화면은 일반 계정으로 직접 데이터를 만든 뒤 다시 확인하세요.

## 3-1. 문제는 메모해 두었다가 한꺼번에 정리하기

문제를 찾을 때마다 바로 이슈나 채팅으로 올리면 목록이 밀리고, 같은 문제가 중복으로 올라갑니다. **메모장에 줄줄이 적어 두고, 화면을 다 본 뒤 한꺼번에 정리**합니다.

메모는 한 줄에 아래 네 가지만 적어도 됩니다. (모르는 건 비워 두세요)

```
화면 / 계정 / 무엇을 눌렀더니 / 어떻게 됐다 (스크린샷 파일 이름)
```

예) `U-12 / 학습자 / 첫 카드의 수강 포기 눌렀더니 / 아무 반응 없음 (shot3.png)`

- 다 보고 나서 메모를 Claude에 붙여넣고 "메모 정리해줘"라고 하면, **모호한 줄은 되물어 본 뒤** 이슈 초안으로 만들어 줍니다. 예를 들어 "버튼이 안 눌림"이라고만 적으면 "어느 화면의 어떤 버튼인가요?"라고 묻습니다.
- **예외:** 앱이 안 뜨거나 서비스를 쓸 수 없는 문제(`P0`), 수업·모의고사 같은 핵심 학습 흐름이 막히는 문제(`P1`)는 모아 두지 말고 **바로 팀 채팅에 알립니다.**
- 마감(목요일 18:00) 전에 고칠 시간이 필요하니, 정리는 **수요일까지** 끝내는 것이 좋습니다.

## 4. 문제를 찾으면 이슈로 올리기

**올리기 전에 이슈 검색**으로 같은 문제가 이미 있는지 봅니다.

### 4-1. 동작 문제 → `🐛 버그 제보`
Issues → New issue → **🐛 버그 제보**를 고르고 아래처럼 채웁니다. (필드 이름은 양식 그대로입니다)

| 칸 | 쓰는 법 | 예 |
|---|---|---|
| 제목 | `[버그]` 뒤에 **어느 화면에서 무엇이 어떻게 되는지** | `[버그] 내 학습에서 수강 포기 후에도 카드가 남음` |
| 🐞 어떤 문제인가요? | 한두 문장 | 수강 포기를 눌러도 목록에서 안 사라진다 |
| 🗂️ 업무 | 해당하는 업무 | `ENR · 수강` |
| 📋 관련 요구사항 · 정책 ID | 알면 적기 | `FR-ENR-005` |
| 🔁 재현 방법 | **계정 + 순서**를 번호로 | 1. 학습자로 로그인 2. `/courses/1` 수강 시작 3. `/my/learning`에서 수강 포기 |
| 🙆 기대한 동작 | 설계서·명세대로라면 | 목록에서 내려가고 토스트가 나온다 |
| 🙅 실제 동작 | 실제로 보인 것 | 카드가 그대로 있다 |
| 📸 스크린샷 | 가능하면 첨부 | |
| 📋 에러 메시지 / 로그 | 화면의 오류 문구, 콘솔·앱 로그 | |
| 💻 발생 환경 | 브라우저, 화면 폭 | Chrome, 데스크톱 |

**좋은 재현 방법:** 처음 보는 사람이 그대로 따라 하면 똑같이 보이는 것. **나쁜 재현 방법:** "안 돼요", "이상해요".

### 4-2. 디자인 문제 → `🔧 작업` + `🎨 design`
글자 크기·간격·정렬·색·모바일 폭에서 깨지는 곳은 **🔧 작업** 양식으로 올리고 `🎨 design` 라벨을 붙입니다. 어느 화면(예: `U-12`)인지와 스크린샷을 꼭 넣습니다.

### 4-3. 라벨·마일스톤
| 항목 | 정하는 법 |
|---|---|
| 타입 | `🐛 bug`(자동) 또는 `🎨 design` |
| 우선순위 | 아래 표 |
| 영역 | `area: …` 라벨 |
| 파트 | `part: FE`, `part: BE`, `part: 공통` 중 해당 라벨 |
| Projects | 팀 보드에 추가 |
| 마일스톤 | 그 기능이 속한 단계와 같게. **P1 기능의 버그는 `3. P1 구현`, P2 기능은 `4. P2 구현`** |
| 담당 | 그 영역 담당(2번 표). 다른 영역이면 이슈에 담당을 적어 알려 주기 |

> ⚠️ 마일스톤이 `3. P1 구현`인 이슈를 고치는 PR은 **P1 PR이라 PM 또는 형상관리 1명 승인이 필요**합니다.
> 다른 묶음의 파일이나 `sql/`도 수정했다면 해당 영역 담당자 또는 DB 담당자의 승인도 받습니다. (묶음 B의 `course`·`quiz`는 영역 담당 승인을 요구하지 않습니다)
> P1이 아닌 PR(P2·P3 등)은 승인 없이 `build` ✅와 리뷰 대화 해결 후 머지합니다.

### 4-4. 우선순위 기준
| 우선순위 | 기준 | 예 |
|---|---|---|
| `P0: 긴급` | 서비스를 쓸 수 없거나 발표·배포가 막힘. 하던 일을 멈추고 처리 | 앱이 실행되지 않음 |
| `P1: 높음` | 가입·진단·수업·모의고사·포트폴리오 등 메인 흐름이 막힘. 또는 주요 기능이 안 되거나 값이 틀리고 우회 방법이 없음 | 퀴즈 제출이 저장되지 않음 |
| `P2: 보통` | 일부 동작이 이상하지만 우회 가능 | 토스트가 두 번 나옴 |
| `P3: 낮음` | 문구·정렬 등 사소한 것 | 버튼 간격이 어긋남 |

## 5. 고칠 때

- 자기 영역 문제는 담당이 고칩니다. 다른 영역 코드는 **그 담당에게 이슈로 알립니다.** (직접 고쳐야 하면 이슈에 이유를 적고 담당에게 알리세요)
- 브랜치: `fix/<이슈번호>-<짧은-영어>`, 커밋·PR 제목: `fix(<영역>): <한국어 제목>`, PR 본문에 `Closes #번호`.
- **이슈 범위 안에서만** 고칩니다. 고치다가 보인 다른 문제는 새 이슈로 올립니다.
- 고친 뒤에 **재현 방법 그대로** 다시 눌러 확인하고, 이슈에 "확인했어요" 한 줄을 남깁니다.

## 6. 확인 기록 (자기 메모용)

한 화면이 끝날 때마다 한 줄씩 적어 두면, 나중에 "무엇을 봤고 무엇이 나왔는지" 말하기 쉽습니다.

| 화면 | 계정 | 결과 | 이슈 번호 |
|---|---|---|---|
| (예시) U-12 내 학습 | 학습자 | 이상 없음 | - |
| (예시) U-13 수업 | 학습자 | 문제 1건 | #번호 (올린 이슈 번호) |

> 위 두 줄은 쓰는 모양을 보여 주는 **예시**입니다. 내 화면으로 바꿔 적으세요.
