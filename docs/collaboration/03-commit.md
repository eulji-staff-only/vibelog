# 03. 커밋 규칙

[← 협업 규칙 README로 돌아가기](../../README.md)

---

## 형식

```
<타입>(<영역>): <제목>          ← 1줄: 필수

<본문>                          ← 선택: 왜 바꿨는지, 무엇이 달라졌는지

<푸터>                          ← 선택: 관련 이슈
```

**예시 (한 줄로 충분한 경우)**

```
feat(quiz): 정답률 계산 함수 추가
```

**예시 (본문까지 쓰는 경우)**

```
fix(quiz): 문제가 0개일 때 정답률이 NaN으로 나오는 문제 수정

문제 수가 0이면 0으로 나누게 되어 NaN이 화면에 표시됐다.
문제 수가 0이면 정답률을 0으로 처리하고, 퀴즈 시작 버튼을 비활성화한다.

Refs: #12
```

## 타입 (type) — 무슨 종류의 변경인가요?

| 타입 | 언제 쓰나요 | 예시 |
|---|---|---|
| `feat` | 새로운 기능 추가 | `feat(quiz): 정답률 50% 이상 통과 판정 추가` |
| `fix` | 버그 수정 | `fix(auth): 새로고침하면 로그아웃되는 문제 수정` |
| `design` | 화면(UI)·CSS 변경 | `design(portfolio): 포트폴리오 카드 레이아웃 변경` |
| `style` | 동작·화면 변화 없는 코드 모양 수정 (들여쓰기, 줄바꿈, 세미콜론) | `style(common): 코드 포매터 적용` |
| `refactor` | 동작은 그대로, 코드 구조 개선 | `refactor(exam): 오답 분석 로직을 별도 함수로 분리` |
| `test` | 테스트 추가·수정 | `test(quiz): 통과 기준 경계값 테스트 추가` |
| `docs` | 문서 수정 (README, 주석 등) | `docs: 커밋 규칙 예시 보완` |
| `chore` | 설정·패키지·빌드 등 기능과 무관한 작업 | `chore(config): 패키지 의존성 업데이트` |

> 🤔 **design vs style 헷갈릴 때:** 화면이 달라지면 `design`, 화면은 그대로이고 코드 모양만 바뀌면 `style`
> 🤔 **fix vs refactor 헷갈릴 때:** 잘못 동작하던 걸 고치면 `fix`, 잘 동작하는데 코드만 정리하면 `refactor`

## 영역 (scope) — 어느 부분을 바꿨나요?

괄호 안의 영역은 **선택**입니다. 여러 영역에 걸치거나 딱 맞는 영역이 없으면 생략하세요. (`docs: …`)

| 영역 | 해당 부분 |
|---|---|
| `auth` | 회원가입 · 로그인 · 계정 |
| `course` | 코스 목록 · 코스 추천 · 코스 선택 |
| `lesson` | 개념 수업 콘텐츠 · 진도 |
| `quiz` | 퀴즈 풀이 · 채점 · 재도전 |
| `assignment` | 실습 스텝 가이드 · 과제 결과물 제출 |
| `agent` | 평가 에이전트 설명 · 가이드 |
| `portfolio` | 포트폴리오 카드 · 템플릿 · 공개 설정 |
| `exam` | 모의고사 · 오답 분석 리포트 |
| `community` | 커뮤니티 공유 · 추천 · 추천 랭킹 |
| `contest` | 월간 콘테스트 · 투표 · 배지 |
| `message` | 쪽지 |
| `admin` | 관리자 · 기관 관리자 기능 |
| `common` | 공통 컴포넌트 · 유틸 · 레이아웃 |
| `config` | 프로젝트 설정 · 빌드 · 배포 · 패키지 |

> 새 영역이 필요하면 혼자 만들지 말고, [규칙 변경 절차](../../README.md#-규칙에-동의하는-방법--규칙을-바꾸는-방법)로 이 표에 먼저 추가합니다.

## 제목 쓰는 규칙

1. **50자 이내**로 짧게
2. **한국어로** 쓰고, "~했음/~합니다" 대신 **"~ 추가", "~ 수정"** 처럼 끝냅니다
3. **마침표(`.`)를 찍지 않습니다**
4. **무엇을 했는지** 구체적으로 씁니다. "수정", "작업" 같은 한 단어는 금지

**자주 쓰는 끝맺음 말**

| 말 | 뜻 | 예시 |
|---|---|---|
| 추가 | 없던 것을 새로 만듦 | `feat(contest): 출품작 투표 버튼 추가` |
| 수정 | 잘못된 것을 고침 | `fix(message): 쪽지 읽음 표시 오류 수정` |
| 변경 | 동작·모양을 다르게 바꿈 | `design(course): 코스 추천 카드 색상 변경` |
| 개선 | 더 좋게 만듦 | `refactor(community): 추천 랭킹 조회 속도 개선` |
| 삭제 | 지움 | `chore: 사용하지 않는 이미지 삭제` |
| 분리 | 하나를 여럿으로 나눔 | `refactor(exam): 리포트 컴포넌트 분리` |
| 이동 | 위치를 옮김 | `refactor(common): 날짜 유틸 파일 이동` |

| | 제목 | 이유 |
|---|---|---|
| ⭕ | `feat(portfolio): 포트폴리오 카드 공개 여부 토글 추가` | 타입·영역·내용 모두 명확 |
| ❌ | `수정` | 무엇을 왜 수정했는지 알 수 없음 |
| ❌ | `feat: 기능 추가.` | 내용이 없고 마침표 사용 |
| ❌ | `퀴즈랑 로그인이랑 포트폴리오 고침` | 타입 없음, 여러 작업이 섞임 |
| ❌ | `Feat(Quiz): Add grading` | 대문자 타입, 우리 팀은 한국어 제목 |

## 본문과 푸터

- **본문**은 "**무엇을**"보다 "**왜**"를 적습니다. 코드를 보면 무엇을 했는지는 보이지만, 왜 그랬는지는 안 보이니까요.
- 제목과 본문 사이는 **한 줄을 비웁니다.**
- **푸터**에 관련 이슈를 `Refs: #12` 형식으로 적을 수 있습니다.

> ⚠️ 커밋 템플릿에서 `#`으로 **시작하는** 줄은 커밋에서 지워집니다. 이슈 번호를 줄 맨 앞에 `#12`로 쓰지 말고 반드시 `Refs: #12`처럼 쓰세요.

---

## 얼마나 자주, 얼마만큼 커밋하나요?

**커밋 1개 = 의도 1개.** 제목을 한 줄로 쓰기 어렵다면 너무 많이 담은 것입니다.

| ⭕ 좋은 커밋 묶음 | ❌ 나쁜 커밋 |
|---|---|
| `feat(quiz): 정답률 계산 함수 추가` | `feat: 퀴즈 기능 + 로그인 버그 수정 + 버튼 색 변경` |
| `feat(quiz): 정답률 50% 기준 통과 판정 추가` | (하루 작업 전체를 커밋 하나로) |
| `design(quiz): 통과·재도전 결과 화면 추가` | |
| `test(quiz): 통과 기준 경계값 테스트 추가` | |

## 커밋 메시지 vs PR 제목 — 무엇이 남나요?

우리 팀은 **Squash merge**를 쓰기 때문에, 브랜치 안의 커밋 여러 개가 `develop`에 합쳐질 때 **커밋 하나로 묶이고, 그 이름은 PR 제목**이 됩니다.

```
내 브랜치의 커밋들                         develop에 남는 것
─────────────────────────────            ──────────────────────────────────────────
feat(quiz): 정답률 계산 함수 추가    ┐
feat(quiz): 통과 판정 추가          ├──▶  feat(quiz): 퀴즈 정답률 계산과 통과 판정 추가 (#15)
fix(quiz): 리뷰 반영 - 0 나누기 수정 ┘                ↑ PR 제목 + PR 번호
```

- 그래서 **PR 제목이 가장 중요합니다.** 반드시 커밋 규칙과 똑같은 형식으로 쓰세요.
- 브랜치 안의 커밋도 규칙을 지켜 주세요. 리뷰어가 작업 과정을 읽기 쉬워지고, 좋은 습관이 됩니다.

## 커밋 템플릿 사용하기

저장소 폴더 안에서 한 번만 실행하면 됩니다. (README의 최초 세팅에 포함)

```bash
git config commit.template .gitmessage.txt
```

이후 `git commit` (뒤에 `-m` 없이)을 치면 규칙 안내가 적힌 템플릿이 열립니다. 맨 윗줄에 제목을 쓰고 저장한 뒤 창을 닫으면 커밋이 완료됩니다. 아무것도 쓰지 않고 닫으면 커밋이 취소됩니다.

> 🤖 AI에게 커밋 메시지를 만들게 해도 됩니다. 단, 이 문서의 형식(타입·영역·한국어 제목)에 맞는지 확인하고 커밋하세요.
