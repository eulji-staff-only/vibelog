# 이벤트 스토밍(2026-11-04)

바이브로그를 이용할 때 일어나는 사건(Event)을 시간 흐름대로 나열해, 백엔드 도메인과 프론트 화면 흐름을 도출한다.

> 2026-10-30 발표 후 변경: 퀴즈 통과 기준, 모의고사·오답 분석 리포트(2-4), 월간 콘테스트(2-8), 추천·랭킹을 추가했다. XP·레벨·연속 학습 일수는 뺐다. 핫스팟은 팀 논의판에서 모두 결정했다(5장).
> 2026-11-03 변경: 학습 구조를 트랙 → 코스 → 수업 → 활동으로 정했다. 수업 안에서 개념·퀴즈를 반복하고(2-3), 모의고사는 수업마다 본다(2-4). 과제 제출과 포트폴리오를 "포트폴리오"로 합쳐 코스 마지막에 한 번 제출한다(2-5).
> 2026-11-03 엔티티 확정(D1~D10) 반영: 커뮤니티를 일반 게시판으로 바꾸고(2-6), 코스 카테고리를 트랙과 따로 두었다. 사용자 차단과 수업 수정 기록은 이번 범위에서 뺐다.
> 2026-11-04 확정 반영: 퀴즈는 별도 퀴즈 화면에서 문항마다 확인하며 풀고(확인한 문항은 답 고정) 마지막에 제출한다. 문항은 객관식 4지선다를 코드 빈칸 채우기 / 개념 문제 / 결과 유추하기 / 낚시 문제 4가지 유형으로 보여준다. 활동·수업의 열림과 완료 시각은 저장한다.

## 0. 전제 (2026-10-29 팀 결정, 2026-11-03 변경)

| 항목 | 결정 |
| --- | --- |
| 사용자 | 학습자, 운영자 2종. 기관 관리자·리뷰어 역할은 두지 않는다. 학습자 4유형(입문 / 제어 / 구조화 / 숙련)은 할 수 있는 행동이 같으므로 액터로 나누지 않는다 |
| 학습 구조 | 트랙 → 코스 → 수업 → 활동. 수업은 개념과 퀴즈가 번갈아 놓인 활동과 마지막 모의고사로 이루어지고, 코스 마지막에 포트폴리오가 있다 |
| 트랙 추천 | 가입 후 진단 설문에서 고른 보기의 트랙 점수를 더해 Starter / Controller / Builder / Explorer 중 합계가 가장 높은 트랙 하나를 추천한다. 설문은 건너뛸 수 있고, 완료·건너뜀을 진단 결과로 저장한다 |
| 코스 선택 | 추천과 관계없이 어떤 트랙의 코스든 자유롭게 고른다. 코스는 트랙 하나와 카테고리 하나에 속한다. 여러 코스를 동시에 수강할 수 있다 |
| 퀴즈 형식 | 객관식 4지선다만 쓴다. 문항은 코드 빈칸 채우기 / 개념 문제 / 결과 유추하기 / 낚시 문제 4가지 유형으로 보여준다. 게임형은 만들지 않는다 |
| 단계 잠금 | **퀴즈 정답률 50% 이상이어야 다음 개념이 열리고**, 마지막 퀴즈를 통과하면 그 수업의 모의고사가 열린다. 모의고사를 보고 리포트를 확인해야 다음 수업이 열린다 |
| 모의고사 | 수업마다 1번. 통과 점수는 없고, 개념별 정답률 리포트를 확인해야 다음으로 넘어간다 |
| 포트폴리오 | 과제와 포트폴리오를 하나로 합친다. 마지막 수업의 리포트를 확인하면 열리고, 제출하면 포트폴리오 카드로 등록된다 |
| 코스 완료 | 모든 수업의 모의고사 응시·리포트 확인 + 포트폴리오 제출. 처음 충족한 시각만 기록한다 |
| 저장하는 값과 계산하는 값 | 활동·수업의 열림과 완료 시각은 저장해 순서가 바뀌어도 다시 잠그지 않는다. 진행률과 코스 완료 여부는 학습 기록에서 계산한다 |
| 평가 에이전트 | 서비스는 포트폴리오 과제에서 에이전트 설명과 설정 파일만 연다. 실행은 학습자 환경에서 하며, 서비스는 실행 결과를 받지 않는다 |
| 커뮤니티 | 일반 게시판(자유게시판 / 질문·답변 / 작품 공유). 글·사진·댓글·답글(한 단계). 추천·랭킹·즐겨찾기는 작품 공유 게시글 기준, 콘테스트 출품·동료 리뷰는 포트폴리오 기준 |
| 부가 기능 | 추천·랭킹, 즐겨찾기·팔로우, 월간 콘테스트, 쪽지, 포트폴리오 템플릿, 동료 리뷰, 알림, 신고(나중에 구현). 사용자 차단은 이번 범위 제외 |
| 보상 | XP·레벨·연속 학습 일수는 두지 않는다. 배지는 월간 콘테스트 1·2·3등에게만 준다 |
| AI 호출 | 서비스 기능에서 AI를 호출하지 않는다. 퀴즈·모의고사 채점, 리포트, 랭킹은 규칙 기반 |
