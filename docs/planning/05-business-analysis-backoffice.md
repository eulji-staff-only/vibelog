# 업무 분석 - 백오피스(2026-11-04)

학습자가 보는 화면이 아니라, 운영자가 서비스를 통제하고 모니터링하는 기능을 정의한다. 이벤트 번호(A1-1 등)는 [이벤트 스토밍](03-event-storming.md)과 같다.

> 2026-10-30 발표 후 변경: 모의고사 문항, FAQ, 수정 내용 기록, 코스 카테고리, 월간 콘테스트 주제, 공지 관리를 추가하고 보상 규칙(XP·레벨) 관리를 뺐다. 결정 필요 항목(6장)은 팀 논의판에서 결정했다.
> 2026-11-03 변경: 학습 구조를 트랙 → 코스 → 수업 → 활동으로 정했다. 코스 카테고리를 트랙으로 바꾸고, 수업 안에 개념·퀴즈 활동과 수업별 모의고사를 등록한다. 실습 과제·FAQ·평가 에이전트 설명은 코스별 포트폴리오 과제로 옮겼다.
> 2026-11-03 엔티티 확정(D1~D10) 반영: 코스 카테고리를 트랙과 따로 두어 다시 관리한다. 진단은 보기별 트랙 점수로 추천한다. 수정 내용 기록과 운영자 작업 기록은 이번 범위에서 뺐다.

## 1. 운영자

| 항목 | 내용 |
| --- | --- |
| 사용자 | 운영자 1종. 기관 관리자·리뷰어 역할은 두지 않는다 |
| 하는 일 | 트랙·코스·수업(개념·퀴즈 활동, 모의고사)·포트폴리오 과제 콘텐츠를 만들고 갱신한다. 트랙·코스 카테고리, 진단 문항과 보기별 트랙 점수, 월간 콘테스트 주제, 공지를 관리한다. 신고와 회원을 처리한다. 학습 지표를 보고 어떤 콘텐츠를 개선할지 판단한다 |
| 접근 | 관리자 권한이 있는 계정만 백오피스에 들어갈 수 있다. 운영자 계정은 DB에 직접 등록한다 |

## 3. 프로세스

### 3-1. 코스·수업 콘텐츠 등록

![코스 수업 콘텐츠 등록](../images/업무분석_백오피스_발표후_3-1.%20코스%20수업%20콘텐츠%20등록%282026-11-03%29.png)

트랙과 카테고리는 코스를 만들기 전에 등록해 둔다 (3-4).

| 단계 | 운영자가 하는 일 | 서비스가 하는 일 |
| --- | --- | --- |
| 1. 코스 생성 | 코스명, 소속 트랙, 카테고리, 코스 목표, 소개, 플랜 일수를 입력한다 | 비공개 상태로 저장한다 |
| 2. 수업 추가 | 수업 제목, 학습 목표, 예상 소요 시간을 입력하고 순서를 정한다 | 수업 순서대로 잠금 규칙을 적용한다 |
| 3. 개념 활동 | 개념 활동을 추가해 글·이미지를 작성(마크다운 ↔ 리치 텍스트)하고 개념 태그와 도구 노트 링크를 단다 | 활동 순서대로 잠금 규칙을 적용한다 |
| 4. 퀴즈 활동 | 개념마다 바로 뒤에 퀴즈를 두고 문항, 보기 4개, 정답, 해설, 개념 태그, 표시 유형(필요하면 코드)을 등록한다. 개념 수만큼 3~4를 반복한다 | 규칙 기반 채점, 50% 통과 판정, 개념별 오답 비율 계산에 쓰인다 |
| 5. 모의고사 | 그 수업의 모의고사 문항을 등록하고, 문항마다 연관 개념을 지정한다 | 개념별 정답률 리포트 계산에 쓰인다 |
| 6. 미리보기·수업 공개 | 학습자 화면으로 확인 후 공개한다 | 공개된 수업만 학습자에게 보인다. 퀴즈가 빠진 개념이나 모의고사 문항이 없으면 공개를 막는다 |
| 7. 포트폴리오 과제 · FAQ | 코스 수업이 다 준비되면 과제 주제, 학습 목표, 스텝 가이드, 자주 막히는 문제(FAQ)를 작성한다 | 마지막 수업 리포트를 확인한 학습자에게 열린다 |
| 8. 평가 에이전트 설명 | 코스 학습 목표에 맞는 에이전트의 세팅·실행 방법, 평가 기준을 쓰고 설정 파일을 올린다 | 포트폴리오 과제 화면에 함께 보인다 |
| 9. 코스 공개 | 코스를 공개한다 | 포트폴리오 과제가 없으면 공개를 막는다 |

### 3-2. 콘텐츠 갱신 (도구 노트 교체 · 수정 내용 기록)

빠르게 바뀌는 도구 사용법은 도구 노트로 분리돼 있으므로, 운영자는 수업 본문을 건드리지 않고 도구 노트 링크만 바꾼다.

수업 목록 → 수업 선택 → 도구 노트 링크 수정 → 저장 (A2-7)

공개된 수업 본문을 고칠 때 바뀐 부분을 기록하고 수강자에게 알리는 기능(A2-11)은 이번 범위에서 뺐다 (D10). 수정하면 학습자 화면에 바로 반영된다.

### 3-3. 신고 처리 (나중에 구현)

![신고 처리](../images/업무분석_백오피스_발표후_3-3.%20신고%20처리.png)

| 단계 | 내용 |
| --- | --- |
| 접수 | 대상(게시글, 포트폴리오, 댓글, 동료 리뷰, 쪽지), 사유, 신고자, 누적 신고 수가 목록에 쌓인다 |
| 자동 숨김 | 누적 신고가 기준(정책 정의서) 이상이면 자동으로 숨기고 운영자 확인을 기다린다 |
| 확인 | 신고 대상 원문과 작성자 이력을 본다. 쪽지는 신고된 쪽지만 볼 수 있다 |
| 숨김 | 학습자 화면에서 내리고 작성자에게 사유를 알린다 |
| 기각 | 신고를 닫는다. 자동 숨김된 콘텐츠면 복구한다 |
| 정지 | 반복 위반 시 기간을 정해 정지한다. 정지 회원은 로그인·작성이 막힌다 |

### 3-4. 진단 규칙 · 트랙 · 카테고리 · 월간 콘테스트 · 공지

진단 설정 → 문항·보기 수정 → 보기마다 트랙과 점수 입력 → 테스트 응답으로 추천 결과 확인 → 저장 (A3-1). 고른 보기의 점수 합계가 가장 높은 트랙을 추천한다. 동점 처리는 미정.

트랙 관리 → 트랙 이름·대상 학습자 유형·설명·순서 입력 → 코스를 트랙에 넣기 → 저장 (A3-4)

카테고리 관리 → 카테고리 이름·순서 입력 → 코스를 카테고리에 넣기 → 저장 (A3-6)

콘테스트 관리 → 이달의 주제·설명 입력 → 출품 기간·투표 기간 지정 → 저장 (A3-3). 투표가 끝나면 서비스가 득표순 1·2·3등을 정하고 배지를 준다. 운영자는 결과를 확인한다.

공지 관리 → 제목·본문 작성 → 배너 노출 여부와 게시 기간 선택 → 게시 (A3-5)

## 4. 예외 프로세스

| 상황 | 처리 |
| --- | --- |
| 관리자 권한 없는 계정이 백오피스 접근 | 접근 막고 학습자 메인으로 보낸다 |
| 필수 항목(개념마다 뒤따르는 퀴즈, 퀴즈 정답, 모의고사 문항 등)이 빈 수업 공개 시도 | 공개 막고 빠진 항목 표시 |
| 포트폴리오 과제가 없는 코스 공개 시도 | 공개 막고 "포트폴리오 과제를 작성하세요" 표시 |
| 연관 개념이 없는 모의고사 문항 저장 | 저장 막고 연관 개념 지정 요청 |
| 학습자가 진행 중인 수업 비공개 / 삭제 시도 | 경고 모달로 영향받는 학습자 수 표시. 삭제 대신 비공개 권장 |
| 수업·활동 순서 변경 시 이미 열린 수업·활동 | 학습자의 열림·완료 상태는 유지한다 |
| 트랙 점수가 없는 진단 보기 저장 | 저장 막고 트랙과 점수 입력 요청 |
| 코스가 들어 있는 트랙·카테고리 삭제 시도 | 삭제 막고 코스를 먼저 옮기라고 안내 |
| 콘테스트 기간이 겹치거나 투표 기간이 출품 기간보다 앞섬 | 저장 막고 기간 오류 표시 |
| 이미 처리된 신고를 다른 운영자가 다시 처리 | 최신 처리 상태를 보여주고 중복 처리 막음 |
| 정지 기간 종료 | 자동으로 해제한다 |
